# 풀 리퀘스트(PR) 규칙 및 템플릿

## 1. 제목 규칙 (Title Convention)
Conventional Commits 형식을 따릅니다:
`<타입>: <간결하고 명확한 작업 요약>`

예시:
- feat: 모바일 집사 핵심 기능 및 페이싱 엔진 구현
- fix: 마감 당일 분량 계산 시 0으로 나누어지는 오류 수정
- refactor: 집사 대화 엔진 구조 개선
- test: 페이싱 엔진 및 우선순위 단위 테스트 추가
- docs: 요구사항 명세서 완료 상태 갱신

## 2. 본문 템플릿 (PR Template)

### 개요 (Overview)
- 변경 사항의 목적과 배경을 요약합니다.

### 작업 내용 (Changes)
- 구현되거나 수정된 주요 기능을 항목별로 나열합니다.

### 요구사항 명세서 매핑 (Requirement Mapping)
- REQ / FUNC 번호와 구현 완료 여부를 명시합니다.

### 테스트 결과 (Test Results)
- 작성한 단위 테스트 목록 및 통과 여부를 기술합니다.

### 체크리스트 (Checklist)
- [x] 빌드 및 단위 테스트가 정상 통과하는가?
- [x] 컨플릭트 마커가 없는가?
- [x] 불필요한 로그나 임시 파일이 포함되지 않았는가?
- [x] 커밋 및 코드에 이모지가 포함되지 않았는가?
