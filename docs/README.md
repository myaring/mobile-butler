# 문서

모바일 버틀러의 기획·설계·개발 기록을 모아두는 폴더입니다. Markdown이 아니어도 됩니다. 기획서, 제안서, 발표 자료, 참고 이미지도 전부 여기에 둡니다.

## 처음 오셨다면

위에서부터 읽으시면 됩니다. 1~4번까지 읽으면 바로 작업을 시작할 수 있습니다.

1. [킥오프 발표 자료](mobile-butler-kickoff.pdf) — 무엇을 만드는 프로젝트인지, 4주 일정이 어떻게 되는지
2. [요구사항 · 기능 명세서](requirement_analysis.md) — 만들 기능 목록입니다. **담당이 비어 있는 항목에서 할 일을 찾으세요**
3. [기여 양식 및 규칙](contribute_rules.md) — 브랜치를 어떻게 따고 커밋 메시지를 어떻게 쓰는지
4. [PR 룰](PR_rules.md) — PR 올리는 방법과 리뷰·머지 절차
5. [기능 정의 초안](draft/hss900606_draft.md) — 전체 기능을 깊게 정의한 장기 문서. 지금 다 읽을 필요는 없고, 맡은 기능이 생겼을 때 해당 부분만 찾아보시면 됩니다

> 3번과 4번은 한 번 읽고 끝나는 문서가 아닙니다. PR을 올릴 때마다 다시 펼쳐보셔도 되고, 그게 정상입니다.

## 어디에 적을까?

| 적으려는 내용 | 위치 |
| --- | --- |
| 만들 기능과 담당자, 완료 기준 | [요구사항 · 기능 명세서](requirement_analysis.md) |
| 화면 디자인 정의 | [디자인](design.md) |
| 오늘 한 작업, 삽질하다 알게 된 것 | [개발 일지](dev-log/README.md) |
| 아직 정리되지 않은 개인 아이디어·초안 | [draft/](draft/) |
| 참고용 이미지, 외부 자료 | [reference/](reference/) |
| 반복해서 쓰는 문서 양식 | [templates/](templates/) |
| 협업 규칙 자체를 바꿀 때 | [기여 규칙](contribute_rules.md) 또는 [PR 룰](PR_rules.md) |
| 앞으로 할 일, 버그 신고, 기능 제안 | GitHub 이슈 (문서로 적지 않습니다) |

마지막 줄이 중요합니다. **할 일 관리는 문서가 아니라 이슈에서 합니다.** 문서에 적은 TODO는 아무도 다시 보지 않습니다.

## 관리 규칙

1. 새 문서를 만들면 위 **문서 목록**에 한 줄 추가합니다. 목차에 없는 문서는 금방 잊힙니다.
2. 아직 다듬어지지 않은 개인 초안은 `draft/`에 둡니다. 정리가 끝나면 `docs/`로 올립니다.
3. 폴더는 **문서가 실제로 쌓여 찾기 어려워졌을 때** 만듭니다. 나중에 쓸 것 같다는 이유로 빈 폴더를 미리 만들지 않습니다.
4. 문서를 옮기면 그 문서를 가리키던 링크도 함께 고칩니다. 링크는 상대경로로 적습니다.
