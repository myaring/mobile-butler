# Room 영속화 구현 (A-5)

- 일자: 2026-10-29
- 작업자: yuhan3958
- 관련: #48 / PR #81

## 한 일

<!-- 무엇을 바꿨는지. 파일 단위로 나열하기보다 "무엇이 가능해졌는지"로 적어주세요. -->

- `Goal`과 `ProgressEntry`를 Room 데이터베이스의 `goals`, `progress_entries` 테이블에 저장할 수 있도록 영속화 계층을 구성했습니다.
- 도메인 모델과 Room Entity를 분리하고 Mapper를 통해 변환하도록 구성하여 도메인 계층이 Room에 직접 의존하지 않도록 했습니다.
- `LocalDate`, `Instant`, `ZoneOffset`, enum 등 도메인 값의 SQLite 저장 표현을 변환하는 Converter를 적용했습니다. 기록 시각과 기록 당시의 UTC offset을 함께 보존하도록 했습니다.
- 목표·진행 기록 DAO를 구현해 Flow 기반 조회, 목표별 기록 조회, 기간별 기록 조회, 추가·수정·삭제를 지원하도록 했습니다.
- 목표 상태·우선순위 인덱스, 기록의 목표 ID·시각 인덱스, 두 테이블 간 외래 키를 정의했습니다. 목표 완료 시 기록이 연쇄 삭제되지 않도록 설계했습니다.
- `endReason`, `endedAt`, `overdueNoticeShown`을 영속화하고 Room 기반 Repository 구현체를 추가했습니다.
- 데이터 저장 후 재조회, 기록 날짜·offset 유지, 우선순위 반영, 완료 상태와 기록 보존 등을 검증하는 테스트를 작성했습니다.

- 이 프로젝트는 `androidx.room3`를 사용하므로 기존 Room 2의 API·import와 혼용하지 않아야 합니다. 초기에 `@Database`가 붙은 클래스가 `androidx.room3.RoomDatabase`를 상속하지 않는다는 KSP 오류가 발생했고, Room 3 상속·import를 바로잡아 `:app:kspDebugKotlin` 빌드를 통과했습니다.
- Kotlin 컴파일 단계도 통과했지만, Windows 로컬 JVM 단위 테스트에서 `UnsatisfiedLinkError: no sqliteJni in java.library.path`가 발생했습니다. 스택 트레이스의 `NativeLibraryLoader.android.kt`를 통해 JVM 테스트에서 Android용 SQLite 네이티브 로더가 선택된 점을 확인했습니다.
- SQLite 의존성의 테스트 런타임 변형을 조정하는 과정에서 잘못된 Gradle 치환 설정으로 의존성 해석 오류가 발생하기도 했습니다. 의존성 트리를 확인해 원래 요청 버전과 실제 선택된 모듈을 구분하는 것이 중요했습니다.
- 이후 로컬 테스트 환경 문제를 해결했습니다.
