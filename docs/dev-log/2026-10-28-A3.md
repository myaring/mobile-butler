## 알게 된 것 / 막힌 것

- 도메인 모델과 저장 구현의 분리가 중요했습니다. Room의 Entity와 DAO를 도메인 모델에 직접 결합하면 화면과 계산 로직까지 저장 방식에 의존하게 됩니다. 따라서 도메인 계층은 순수 Kotlin 모델과 Repository 인터페이스만 포함하도록 구성했습니다.
- 기록 시각과 기록 날짜는 서로 다른 개념입니다. Instant만 저장하면 기기 시간대 변경 시 과거 기록의 날짜가 달라질 수 있습니다. 이를 방지하기 위해 #52에서 확정된 ZoneOffset 보존 방식을 적용했습니다.
- 목표의 종료 여부와 마감 경과 여부도 구분해야 합니다. 마감이 지났다는 사실은 현재 날짜로 계산할 수 있으므로 별도 상태로 저장하지 않고, 사용자가 목표를 끝낸 결과만 COMPLETED, endReason, endedAt으로 보존합니다.
- Repository 인터페이스의 정의만으로 저장 연산의 원자성이 보장되지는 않습니다. 목표 완료 시 상태와 종료 정보가 함께 저장되어야 하며, 여러 목표의 우선순위 변경도 일괄 처리되어야 합니다. 실제 트랜잭션 보장은 #48의 Room 구현에서 처리해야 합니다.
- 일부 정책은 아직 후속 이슈와 합의가 필요합니다. Repository 함수의 최종 명칭, 완료 취소 가능 시점, 목표 ID 생성 위치 및 동일 우선순위 정렬 규칙은 관련 구현과 함께 확정해야 합니다.
