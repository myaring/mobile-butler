# 개발 일지

개발 일정과 개발 내용을 기록하는 문서입니다.

## 작성 가이드

**한 줄로 끝나는 작업은 아래 타임라인 표에 한 줄만 추가**하고, **설명이 필요한 작업은 이 폴더에 파일을 만들어** 표에서 링크합니다.

| 어떤 작업인가 | 어디에 적는가 |
| --- | --- |
| 종속성 추가, 문서 오타 수정, 설정 변경 등 한 줄로 설명되는 작업 | 타임라인 표에 한 줄 |
| 기능 구현, 설계 선택, 삽질하다 알아낸 것 등 나중에 근거를 되짚을 작업 | 이 폴더에 `YYYY-MM-DD-주제.md` 파일 + 표에 링크 |

- **작업한 PR에 같이 담아주세요.** 따로 PR을 올릴 필요는 없습니다
- 상세 파일은 [템플릿](../templates/dev-log-template.md)을 복사해서 쓰시면 됩니다. 파일 이름은 `2026-10-21-goal-input-screen.md`처럼 날짜 + 영문 소문자·하이픈입니다
- 표는 **날짜순(오래된 것 위)**이고, 새 줄은 맨 아래에 추가합니다
- 오타 수정처럼 기록할 가치가 없는 작업은 적지 않아도 됩니다

적지 않는 것도 정해두면 편합니다. 일지는 **"무엇을 했는지"**만 남기는 곳입니다.

- 앞으로 할 일, TODO → GitHub 이슈에 등록해주세요
- 기능 명세, 시스템 설명 → [docs](../README.md) 아래 해당 문서에 적어주세요
- 긴 코드 블록, 테스트 출력 전문 → 핵심 몇 줄만 남겨주세요

> 표에 줄을 추가하다 충돌(conflict)이 나면, **두 사람의 줄을 둘 다 남기고** `<<<<<<<`, `=======`, `>>>>>>>` 표시만 지우면 됩니다. 일지 충돌은 이렇게 해결해도 아무 문제가 없습니다.
