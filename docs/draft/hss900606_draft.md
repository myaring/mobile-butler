## 1. 제품 한 줄 정의

> **사용자가 세운 정량적 목표를, 그 사람의 생활 패턴에 맞춰 "오늘 할 몫"으로 쪼개주고, 집사 캐릭터가 적절한 시점에 찔러주는 앱.**

기존 습관/투두 앱과의 차별점은 네 가지입니다.

1. **목표를 날짜로 나눈다** — "책 다 읽기"가 아니라 "오늘 23쪽". 남은 양 ÷ 남은 날로 매일 재계산합니다.
2. **생활 패턴을 안다** — 기상·취침·식사·출퇴근 시간을 알고 있어서, 자는 시간에 물 마시라고 하지 않습니다.
3. **집사에 성격이 있다** — 같은 상황에서도 선택한 페르소나에 따라 말투와 압박 강도가 달라집니다.
4. **기록이 쌓이는 걸 보여준다** — 아래 "동기부여 모델" 참고.

### 동기부여 모델 — 채워진 기록이 주는 성취감

이 앱이 사용자를 움직이는 **1차 동력은 알림이 아니라 트래커입니다.** 알림은 행동을 유도하고, 트래커는 계속하게 만듭니다.

> 오늘 이만큼 했다를 기록하고, 그 기록이 채워져 있는 걸 보면 "어제 뭐라도 했구나" 하는 성취감이 생깁니다.
> **느려도 꾸준히 갈 수 있다는 용기**를 주는 쪽으로 설계합니다.

킥오프 자료의 **"미완료는 실패가 아니다"** 와 같은 이야기입니다. 이 문장이 제품의 기준선이므로, 화면과 문구에서 이걸 어기는 요소가 있으면 그쪽을 고칩니다.

이 원칙에서 따라 나오는 설계 규칙들입니다. 화면과 문구를 만들 때 기준으로 삼습니다.

| 규칙 | 의미 |
| --- | --- |
| **부분 달성도 기록이다** | 목표가 23쪽인데 5쪽만 읽어도 그 날은 "한 날"로 칠해집니다. 달성/미달성 이분법으로 칠하면 대부분의 칸이 비어 보여서 역효과가 납니다 |
| **누적을 전면에 둔다** | "오늘 못 했다"보다 "지금까지 142쪽 읽었다"가 더 크게 보여야 합니다 |
| **빈 칸을 벌하지 않는다** | 못 한 날은 붉은색이 아니라 그냥 옅은 회색입니다. 실패 표시가 아니라 아직 안 칠해진 칸입니다 |
| **속도보다 연속성** | "하루 평균 9쪽" 같은 속도 지표보다 "32일 중 24일 기록" 같은 꾸준함 지표를 앞세웁니다 |
| **집사도 기록을 근거로 말한다** | "3일 연속 기록하셨습니다"처럼 쌓인 걸 짚어주는 멘트를 페르소나별로 준비합니다 |

구현상으로는 **홈의 기록 스트립**과 **목표 상세의 달력 히트맵**이 이 모델을 실어 나르는 화면입니다. 둘 다 Phase 1~2 안에 들어가야 제품이 성립합니다.

## 2. 핵심 사용자 여정

```
[온보딩] 생활 패턴 입력 + 집사 설정
    ↓
[하루 루틴] 타임라인으로 확인 / 편집
    ↓
[목표 생성] 무엇을 / 얼마나 / 언제까지 (+ 현실성·건강 검증)
    ↓
[페이싱 계산] 오늘 할 분량 자동 산출
    ↓
[실행 & 기록] 수동 입력 or 헬스 API 자동 연동
    ↓
[기록 누적] 기록 스트립 / 히트맵이 채워짐 ← 핵심 동기부여
    ↓
[집사 알림] 생활 패턴 기반 시점에 리마인드 / 칭찬 / 추궁
    ↓
[재계산] 밀린 만큼 남은 날에 재분배
    ↓
[마감 임박] D-7 / D-3 / D-1 / 당일 — "거의 다 왔습니다"
    ↓
[주간 리포트] 달성률 회고 + 목표 난이도 조정 제안
```

## 3. 기능 정의

### 3.1 온보딩 — 생활 패턴 프로파일링

알림 시점을 결정하는 근거 데이터이므로, 목표 생성보다 **먼저** 받아야 합니다. 다만 질문이 길면 이탈하므로 **필수 3개 + 선택 N개**로 나눕니다.

**필수 입력**

| 항목 | 입력 형태 | 용도 |
| --- | --- | --- |
| 기상 시각 | 시각 피커 | 알림 가능 시간대 시작점 |
| 취침 시각 | 시각 피커 | 알림 가능 시간대 종료점 (이후 무음) |
| 요일 패턴 | 평일/주말 구분 토글 | 평일·주말 다른 스케줄 적용 |

**선택 입력 (나중에 설정에서 추가 가능)**

- 식사 시각 (아침/점심/저녁) — 식후 복용·식후 산책류 목표의 앵커
- 출퇴근/등하교 시각 — 이동 시간대를 걷기 목표에 활용, 반대로 집중형 목표는 회피
- 방해 금지 시간대 (업무 집중, 회의 등) — 다중 구간 지정
- 주 활동 요일 (운동 가능 요일 등)

**패턴 학습(후순위)**: 사용자가 실제로 체크한 시각을 누적해서 "이 사람은 알림을 보통 22시에 처리한다"를 학습하고 알림 시각을 보정합니다. MVP 이후 과제.

#### 하루 루틴 — 생활 패턴을 눈으로 보기

위에서 받은 값들은 지금까지 **알림 스케줄러만 쓰는 내부 데이터**였습니다. 이걸 **사용자가 직접 보고 편집하는 하루 루틴 화면**으로 올립니다.

- 기상·식사·출퇴근·취침이 **타임라인 블록**으로 배치된 하루를 보여줍니다.
- 사용자가 블록을 **추가·이동·삭제**할 수 있습니다. (운동 19:00~20:00, 독서 22:00~22:30 등)
- 루틴 블록에 **목표를 연결**할 수 있습니다. "22:00 독서 블록 ← 『불변의 법칙』 목표". 연결하면 집사가 그 시각에 알림을 보냅니다.
- 평일 / 주말 루틴을 따로 둡니다.

**이게 왜 중요한가**: 지금 구조에서 알림 시점은 집사가 알아서 정하는 블랙박스입니다. 사용자가 "왜 이때 알림이 오지?"를 알 수 없고 고칠 수도 없습니다. 루틴 화면은 그 스케줄을 **눈에 보이게 만들고 직접 고치게 하는 장치**입니다.

> 킥오프 때 참고한 [레퍼런스 이미지](../reference/ref_daily-dashboard-1.png)의 타임라인 UI가 여기에 맞습니다.
> 홈은 카드 리스트로 가되, **타임라인은 이 루틴 화면에서 살립니다.**

화면 정의는 3.8 ④ 참고.

#### 목표 유형 체계 (개정)

위 카탈로그를 기존 4유형에 대입해보면 **담기지 않는 것이 세 부류** 있습니다.

1. **"~이하로 줄이기"** — 금연, 카페인 2잔 이하, SNS 1시간 이하, 커피값 월 5만 원 이하.
   기존 유형은 전부 "많이 할수록 좋음"을 전제합니다. 적을수록 좋은 목표는 진행률 표시도, 알림 문구도, 달성 판정도 전부 반대로 동작해야 합니다.
2. **일 단위로 쪼개면 이상한 목표** — 1년에 1,200만 원 모으기를 일 할당으로 내리면 "오늘 32,877원 저축"이 됩니다. 월급은 한 달에 한 번 들어오는데요.
3. **수량이 아니라 항목이 중요한 목표** — 여행지 10곳, 자격증 취득 준비. "3/10"보다 *어떤 걸* 했는지가 핵심입니다.

**해결 방향: 유형을 늘리기보다 축을 추가합니다.** 1번과 2번을 각각 새 유형으로 만들면 "상한 일일형 / 상한 빈도형 / 월간 누적형..." 식으로 조합 폭발이 일어납니다. 대신 모든 유형에 공통으로 걸리는 **속성 2개**를 추가합니다.

| 축 | 값 | 의미 |
| --- | --- | --- |
| **방향 `direction`** | `UP` / `DOWN` | 목표치 **이상** 달성 vs 목표치 **이하** 유지 |
| **페이싱 주기 `pacingPeriod`** | `DAY` / `WEEK` / `MONTH` | 할당량을 어느 단위로 쪼개 보여줄지 |

그리고 3번만 **체크리스트형**으로 유형 하나를 추가합니다. 최종 **5유형 + 2축**입니다.

| 유형 | 설명 | 예시 | 계산 방식 |
| --- | --- | --- | --- |
| **누적형 (Cumulative)** | 마감일까지 총량을 쌓음 | 책 380쪽, 러닝 100km, 저축 1,200만 원 | `남은 양 ÷ 남은 주기 수` |
| **도달형 (Target Value)** | 현재 수치를 목표 수치로 이동 | 85kg → 75kg, 토익 750 → 900 | 주간 목표 라인 + 안전 범위 검증 |
| **반복형 (Recurring)** | 주기마다 리셋, 누적 안 됨 | 물 2,000ml, 카페인 2잔 이하 | 주기마다 리셋 + 연속 달성(streak) |
| **빈도형 (Frequency)** | 기간 내 횟수 | 주 3회 운동, 배달 월 4회 이하 | 잔여 횟수 ÷ 잔여 기간 |
| **체크리스트형 (Checklist)** | 정해진 항목을 하나씩 완료 | 여행지 10곳, 자격증 준비 단계 | 완료 항목 수 ÷ 전체 항목 수 |

> 기존 "일일 반복형"은 주기 축이 생겼으므로 **반복형**으로 이름을 바꿉니다. (`pacingPeriod=DAY`가 기본값)

#### 방향 축(`direction`)이 바꾸는 것들

`DOWN` 목표는 단순히 부호만 뒤집는 게 아니라 **UX 전반이 달라집니다.** 구현 전에 합의가 필요한 부분입니다.

| 항목 | `UP` (물 2,000ml) | `DOWN` (카페인 2잔 이하) |
| --- | --- | --- |
| 진행률 바 | 채워 나감 — 가득 차면 성공 | **남은 여유분이 줄어듦** — 바닥나면 실패 |
| 달성 판정 시점 | 목표치 도달 즉시 성공 | **주기가 끝나야 성공 확정** (하루가 끝나야 지킨 것) |
| 기록 입력의 의미 | 잘한 일 (`+200ml`) | 소비한 일 (`커피 1잔 마심`) |
| 알림 성격 | 독려 — "아직 800ml 남았습니다" | **경고** — "한 잔 남았습니다" / "초과하셨습니다" |
| 미기록 처리 | 안 한 것 = 미달성 | **안 한 것 = 지킨 것**으로 볼지 논의 필요 |
| 연속 기록 | 달성한 날 수 | 지킨 날 수 (금연 n일째) |

**마지막 행이 핵심 설계 쟁점입니다.** `UP` 목표는 기록이 없으면 안 한 것이지만, `DOWN` 목표는 기록이 없을 때 "안 마셨다"인지 "마셨는데 입력을 안 했다"인지 알 수 없습니다. 제안: **`DOWN` 목표는 기본값을 0(지킴)으로 두고, 어긴 경우에만 입력**받습니다. 입력 부담이 훨씬 적고 금연·금주 같은 목표의 성격에도 맞습니다.

**금지형(목표치 0)의 표시**: 금연·금주는 `반복형 + DOWN + 목표치 0`으로 모델링되지만, 화면에서는 진행률 바 대신 **"금연 23일째" 카운터**를 메인으로 보여줍니다. 유형을 따로 만들 필요는 없고 표시 방식만 분기하면 됩니다.

---

#### 페이싱 주기(`pacingPeriod`)가 필요한 이유

누적형의 할당량 계산을 항상 일 단위로 하면 깨지는 목표가 있습니다.

| 목표 | 일 단위로 쪼개면 | 적절한 주기 |
| --- | --- | --- |
| 책 380쪽 (43일) | "오늘 9쪽" — 자연스러움 | `DAY` |
| 주 3회 운동 | "오늘 0.43회 운동" — 무의미 | `WEEK` |
| 1년 1,200만 원 저축 | "오늘 32,877원" — 무의미 | `MONTH` |
| 체중 10kg 감량 | "오늘 0.11kg" — 측정 노이즈 이하 | `WEEK` |

주기를 명시하면 집사 멘트도 자연스러워집니다. "이번 달 100만 원 중 40만 원 모으셨습니다"가 "오늘 32,877원 모으세요"보다 훨씬 말이 됩니다.

#### 측정 주기(`measurementCadence`) — 도달형 전용

도달형 중에는 **측정 자체가 자주 불가능한** 목표가 있습니다. 토익 점수는 두 달에 한 번, 체지방률은 인바디 측정할 때만 알 수 있습니다. 이런 목표에 매일 "오늘 몇 점이신가요?"라고 물으면 안 됩니다.

- `DAILY` — 체중 (매일 측정 유도)
- `WEEKLY` — 체지방률, 둘레
- `EVENT` — 토익 점수 등. 알림 없이 **값이 갱신될 때만** 진척을 갱신하고, 중간에는 "다음 시험까지 D-n"만 표시

제목            : "불변의 법칙 완독"
유형            : 누적형
방향            : ↑ 늘리기            ← 신규
측정 단위       : 쪽 (page)

우선순위        : 드래그 정렬

#### 현실성 검증 (중요)

목표 생성 시 **달성 불가능하거나 위험한 목표는 집사가 경고**합니다. 이게 "집사"다운 포인트입니다.

- 누적형: 주기당 할당량이 비현실적이면(예: 하루 200쪽) 경고
- 물: 과수분 섭취 상한 경고
- `DOWN` 목표: 현재 습관 대비 감축 폭이 과하면 단계적 목표 제안 (하루 20개비 → 0 보다 10 → 5 → 0)
- 총 목표 개수가 많을 때: 홈 노출 개수 제한 안내 (3.7 참고)

#### 다이어트 목표의 건강 가드레일 (필수)

**체중·BMI·체지방 목표는 사용자의 건강에 직접 영향을 주므로 별도로 다룹니다.** 앱이 무리한 감량을 거들면 안 된다는 데 합의했습니다. 단계는 세 가지입니다.

| 단계 | 조건 | 동작 |
| --- | --- | --- |
| **안내** | 주당 감량 0.5~1% 구간 | 그대로 진행. "건강한 속도입니다" 확인 멘트 |
| **경고** | 주당 감량이 체중의 1% 초과 | 경고 표시 + **마감일 연장 또는 목표치 완화 제안**. 사용자가 무시하고 진행은 가능 |
| **차단** | 목표 BMI 18.5 미만 | **목표 생성 자체를 막습니다.** 저체중 구간으로 내려가는 목표는 받지 않습니다 |

**경고 문구는 페르소나를 타지 않습니다.** 표독 집사라도 건강 경고에서는 압박하지 않고 중립적인 톤으로 말합니다. 재미를 위해 위험한 목표를 부추기는 멘트가 나오면 안 됩니다.

**추가로 지킬 것**

- 체중 목표에는 **현재 키**를 함께 받아 BMI를 계산합니다. 키 없이는 저체중 판정을 할 수 없습니다.
- 감량 중에도 **실제 감량 속도가 주당 1%를 넘으면 진행 중 경고**를 보냅니다. 생성 시점만 검사하면 의미가 없습니다.
- "저는 의료 전문가가 아닙니다" 성격의 **면책 문구**를 체중 목표 생성 시 1회 노출합니다.
- 미성년자·임신 등은 판별할 수 없으므로 다루지 않되, 면책 문구에 포함합니다.

> 논의 필요: 차단 기준을 BMI 18.5로 둘지, 더 보수적으로(예: 20) 갈지.
> 그리고 "차단"이 정말 생성 불가인지, 강한 경고 후 진행 가능인지.

### 3.3 페이싱 엔진 (주기별 분량 계산)

#### 누적형 기본 식

```
이번 주기 할당량 = ceil( (목표치 - 현재 누적) / 남은 주기 수 )
남은 주기 수 = pacingPeriod 기준으로 마감일까지 남은 일/주/월 수  (휴식일 제외)
```

주기가 끝날 때마다 재계산하므로 **지난 주기에 밀린 양은 남은 주기에 자동 분산**됩니다. 핵심은 "밀렸다"를 벌점으로 쌓지 않고 분량으로 되돌리는 것입니다.

#### 재분배 정책

| 상황 | 동작 |
| --- | --- |
| 하루 미달 | 조용히 남은 날에 분산 |
| 3일 연속 미달 | 집사가 개입: 목표 하향 조정 or 마감일 연장 제안 |
| 재계산 후 일일 할당량이 초기 대비 2배 초과 | "이 속도로는 어렵습니다" 경고 + 조정 플로우 진입 |
| 초과 달성 | 남은 날 할당량 감소 + "미리 벌어둔 분량" 표기 |

#### 도달형(감량 등) 페이싱

일일 변화량이 아니라 **주간 목표 라인**으로 보여줍니다. 체중은 하루 단위 변동이 노이즈라 일 단위 압박이 무의미하기 때문입니다.

```
이번 주 목표 체중 = 시작 체중 - (주당 감량 속도 × 경과 주차)
표기: "현재 81.2kg / 이번 주 라인 81.0kg — 0.2kg 뒤처짐"
```

측정 주기가 `EVENT`인 목표(토익 점수 등)는 페이싱 라인을 그리지 않습니다. 마지막 측정값과 목표값의 격차, 그리고 다음 측정 예정일까지의 D-day만 보여줍니다.

#### `DOWN` 목표의 페이싱

"줄이기" 목표는 할당량을 나눌 게 아니라 **예산(budget)** 개념으로 다룹니다.

```
이번 주기 예산    = 목표 상한값
남은 예산        = 상한값 - 이번 주기 사용량
주기 종료 시점에  남은 예산 >= 0 이면 달성
```

재분배도 반대로 동작합니다. 초과한 날의 양을 다음 날 예산에서 깎을지(엄격) 아니면 주기마다 독립적으로 리셋할지(관대) 선택이 필요한데, **리셋 방식을 기본**으로 제안합니다. 어제 과음했다고 오늘 예산을 마이너스로 시작하면 바로 포기하게 됩니다.

단, **주/월 단위 `DOWN` 목표는 예산 소진 속도를 추적**해야 합니다. 월 5만 원 커피값인데 1주 차에 4만 원을 썼다면 그 시점에 경고해야 의미가 있습니다.

```
경고 조건: (사용량 / 상한값) > (경과 기간 / 전체 기간) + 여유 버퍼
```

#### 체크리스트형 페이싱

항목에 개별 마감일이 없으면 `남은 항목 수 ÷ 남은 주기 수`로 "이번 주에 2개"를 제시합니다. 항목별 마감일이 있으면 가장 가까운 항목만 표시합니다.

### 3.4 진행 기록 (수동 + 자동)

#### 수동 입력

- **홈 카드에서 바로 입력**: 카드 위 `+` 버튼 → 숫자 패드 or 스텝퍼
- **퀵 액션**: 자주 쓰는 증분을 버튼화 (물 `+200ml` `+500ml`, 독서 `+10쪽`)
- **알림에서 바로 입력**: 알림 액션 버튼으로 앱 진입 없이 기록 (`마셨어요` / `나중에`)
- **기록 수정/삭제**: 잘못 입력한 값 되돌리기 — 이력 화면에서 수정
- **`DOWN` 목표는 어겼을 때만 입력**: 기본값이 0(지킴)이므로 평소엔 아무것도 하지 않아도 됩니다. 카드의 버튼도 `+` 가 아니라 `피웠어요` / `마셨어요` 같은 **자진 신고 버튼**이 됩니다.
- **체크리스트형은 항목 탭으로 완료 처리**: 숫자 입력 없음

#### 자동 연동 — Health Connect

Android 14+ 기본 탑재, 그 이하는 Play Store 앱 설치. `androidx.health.connect:connect-client` 사용.

| 목표 | Health Connect Record |
| --- | --- |
| 걸음 수 | `StepsRecord` |
| 거리 | `DistanceRecord` |
| 체중 / BMI | `WeightRecord` + `HeightRecord` |
| 물 섭취 | `HydrationRecord` |
| 운동 | `ExerciseSessionRecord` |
| 수면 | `SleepSessionRecord` |
| 소모 칼로리 | `ActiveCaloriesBurnedRecord` |

**설계 시 주의할 점**

- 권한은 **목표 생성 시점에만** 요청합니다. 온보딩에서 전부 요청하면 거부율이 급증합니다.
- 권한 거부 시 해당 목표는 **수동 모드로 자동 전환** (기능 차단 ✕)
- 동기화 주기: 앱 진입 시 + `WorkManager` 주기 작업(1시간). 알림 발송 직전에도 한 번 당겨서 "이미 달성했는데 알림 오는" 상황을 막습니다.
- 중복 집계 방지: 자동 연동 목표는 수동 입력을 막거나, 수동 입력 시 "보정값"으로 별도 기록합니다.
- iOS 확장을 고려한다면 HealthKit과의 추상화 레이어를 미리 분리해두는 게 좋습니다. (`HealthDataSource` 인터페이스)

### 3.5 집사 알림 엔진

이 앱의 **핵심 차별 기능**입니다. "언제 보낼지"와 "뭐라고 말할지"를 분리해서 설계합니다.

#### (A) 언제 보낼까 — 스케줄링

목표 유형 + 생활 패턴 조합으로 알림 슬롯을 자동 배치합니다.

| 목표 유형 | 기본 배치 규칙 |
| --- | --- |
| 물 마시기 | 기상 ~ 취침 2시간 전까지 2~3시간 간격 분산 |
| 걷기 | 퇴근 시각 직후 1회 + 21시 미달 시 1회 |
| 독서 | 취침 1시간 전 |
| 체중 | 기상 직후 (공복 측정 유도), 주 2~3회 |
| 운동 | 사용자 지정 운동 가능 요일의 선호 시간대 |
| 금연·절제 (`DOWN`) | **정기 리마인드 없음.** 예산 소진 임박 시, 그리고 주기 종료 시 격려만 |
| 저축 등 월 단위 | 급여일 직후 1회 + 월말 정산 1회 |

**공통 규칙**

- 취침 ~ 기상 사이는 **무조건 무음** (예외 없음)
- 방해 금지 시간대 회피
- **하루 총 알림 상한** 설정 (기본 6회) — 초과 시 우선순위 높은 목표만 발송
- **이미 달성한 목표는 발송 취소** (발송 직전 재확인)
- 목표가 여러 개일 때 **같은 시간대에 몰리지 않도록** 최소 30분 간격 확보
- 사용자가 연속으로 무시하면 해당 목표 알림 빈도 자동 감소 (알림 피로 방지)
- **루틴 블록에 연결된 목표는 그 블록 시각을 우선**합니다 (3.1 하루 루틴 참고). 자동 배치는 연결되지 않은 목표에만 적용됩니다.

#### (A-2) 마감 임박 알림 — 필수

목표에 마감일이 있으면 **마감 직전과 당일에 반드시 알림을 보냅니다.** 성격은 독촉이 아니라 **"거의 다 왔다"는 인지와 격려**입니다. 마지막 구간에서 한 번 더 밀어주면 끝낼 수 있는 목표를 놓치지 않게 하는 장치입니다.

| 시점 | 내용 |
| --- | --- |
| **D-7** | 남은 분량 환기 — "일주일 남았습니다. 38쪽 남으셨네요" |
| **D-3** | 남은 분량 + 하루 할당량 재확인 |
| **D-1** | 완주 가능 여부에 따라 분기 (아래 참고) |
| **D-DAY** | 당일 아침 1회 + 미완료 시 저녁 1회 |

**D-1 / 당일 분기**

| 상태 | 톤 |
| --- | --- |
| 남은 양이 하루 할당량 이하 — **끝낼 수 있음** | "오늘 12쪽만 더 하시면 완주입니다. 거의 다 오셨습니다" — 가장 강하게 밀어주는 구간 |
| 남은 양이 많아 **사실상 어려움** | 완주를 종용하지 않습니다. "380쪽 중 310쪽까지 오셨습니다" 식으로 **지금까지의 성취를 먼저** 말하고, 마감일 연장을 제안합니다 |

> 마감 임박 알림은 **알림 상한(기본 6회)의 적용을 받지 않습니다.** 놓치면 안 되는 알림이기 때문입니다.
> 마감일이 없는 반복형 목표에는 해당하지 않습니다.

#### (B) 뭐라고 말할까 — 페르소나 × 상황

메시지 = `{페르소나} × {상황 카테고리} × {목표 데이터}` 조합의 템플릿입니다.

**상황 카테고리**

| 코드 | 상황 |
| --- | --- |
| `REMIND` | 평시 리마인드 |
| `NUDGE_BEHIND` | 오늘 분량 미달 상태에서의 독촉 |
| `PRAISE_DONE` | 일일 목표 달성 |
| `PRAISE_STREAK` | 연속 달성 기록 갱신 |
| `RECOVER` | 연속 실패 후 복귀 유도 |
| `REPORT_WEEKLY` | 주간 리포트 |
| `DEADLINE_NEAR` | **마감 임박** — 독촉이 아니라 "거의 다 왔다" 톤 (위 상세 참고) |
| `DEADLINE_TODAY` | **마감 당일** |
| `BUDGET_WARN` | **`DOWN` 목표 — 예산 소진 임박** ("커피 한 잔 남았습니다") |
| `BUDGET_EXCEEDED` | **`DOWN` 목표 — 상한 초과** |
| `KEPT_CLEAN` | **`DOWN` 목표 — 주기를 지킨 채로 마감** ("오늘도 지키셨습니다. 23일째입니다") |

**페르소나별 톤 (킥오프 안 기준)**

| 페르소나 | 톤 | `NUDGE_BEHIND` 예시 |
| --- | --- | --- |
| 표독 집사 | 직설적·압박형 | "23쪽입니다. 어제도 같은 말씀을 드렸습니다만." |
| 안정 집사 | 차분·지지형 | "오늘 23쪽 남았습니다. 천천히 하셔도 괜찮습니다." |
| 불안 집사 | 과몰입·호들갑형 | "주, 주인님... 23쪽이... 이대로면 큰일인데요...!" |

> 구현 메모: 메시지는 하드코딩이 아니라 **페르소나별 템플릿 리소스**로 관리합니다.
> 같은 상황에 템플릿 3~5개를 두고 랜덤 선택해야 반복감이 줄어듭니다.
> `"{남은량}{단위}입니다. {수식어}"` 형태의 플레이스홀더 치환 방식.

### 3.6 집사 캐릭터 커스터마이징

#### 먼저 — "집사 유형"과 "집사 말투"는 다른 축입니다

킥오프 자료와 브레인스토밍에서 나온 집사 분류가 **서로 다른 것을 가리키고 있어** 용어를 정리합니다.

| 축 | 값 | 무엇을 정하는가 | 언제 |
| --- | --- | --- | --- |
| **집사 유형 (동작 방식)** | 유연형 / 시간표형 / 혼합형 | 목표를 **어떤 방식으로 관리**하는지. 유연형은 분량을 쪼개 주고, 시간표형은 시간 블록에 배치 | 유연형 = 시즌 1, 시간표형 = 시즌 3 |
| **집사 말투 (페르소나)** | 표독 / 안정 / 불안 | 같은 상황에서 **어떤 톤으로 말하는지** | 시즌 2 |
| **집사 외형** | 사용자 업로드 이미지 | 아바타로 보이는 그림 | 시즌 2 |
| **집사 이름** | 자유 입력 | 호칭 | 시즌 2 |

**이 문서의 3.1~3.8은 전부 "유연형 집사"를 전제로 쓰였습니다.** 시간표형은 3.8 ④ 하루 루틴 화면이 그 씨앗이고, 시즌 3에서 본격화됩니다.

세 축은 서로 독립이라 "내가 올린 고양이 사진 + 표독 말투 + 유연형" 같은 조합이 가능합니다.

#### 외형 · 이름 · 말투 설정

| 요소 | 결정 방식 |
| --- | --- |
| 외형 | 사용자 이미지 업로드 (기본 제공 이미지도 몇 개 준비) |
| 이름 | 사용자 직접 입력 (미입력 시 "집사") |
| 말투 | 페르소나 3종 중 택1 |

**구현 메모**

- Android 13+ **Photo Picker**(`PickVisualMedia`)를 쓰면 저장소 권한 요청 없이 이미지를 고를 수 있습니다. 13 미만은 AndroidX 백포트가 자동 처리합니다.
- 선택한 이미지는 URI만 들고 있으면 안 됩니다. 원본이 삭제되거나 권한이 만료되면 깨지므로, **앱 내부 저장소에 복사**한 뒤 그 경로를 저장합니다.
- 업로드 시 **원형 크롭 + 리사이즈**(512px 내외)를 거쳐 용량을 제한합니다.
- 사용처: 홈 상단 멘트 옆 아바타, 알림의 라지 아이콘, 리포트 총평, 온보딩.
- 기본 이미지를 3~4종 넣어두면 업로드를 건너뛴 사용자도 빈 화면을 보지 않습니다.

> 논의: 하나의 이미지만 쓸지, **상황별 이미지 여러 장**(평시 / 칭찬 / 독촉)을 올리게 할지.
> 후자가 훨씬 재밌지만 온보딩 부담이 커지므로, 1장 필수 + 추가 등록은 선택으로 두는 안을 제안합니다.

### 3.7 다중 목표 & 우선순위

- 활성 목표 리스트를 **드래그로 순서 변경**
- 우선순위가 쓰이는 곳
  1. **홈 화면 상단 노출 대상 선정** (아래 참고)
  2. 알림 상한 초과 시 발송 대상 선정
  3. 알림 시간대 충돌 시 선점권
- **보관(archive)** 기능: 삭제하지 않고 비활성화 → 기록은 유지

#### 목표 개수 제한 — 개수가 아니라 노출을 제한한다

**목표를 몇 개까지 만들 수 있는지는 제한하지 않습니다.** 대신 **홈 화면에 펼쳐 보이는 것만 상위 3개로 제한**합니다.

| 구분 | 정책 |
| --- | --- |
| 생성 가능 개수 | 제한 없음 |
| 홈 화면 펼침 | **우선순위 상위 3개** |
| 나머지 | **"더보기"로 접어둠**. 펼치면 축약 카드(제목 + 진행률 바)로 표시 |

이렇게 하는 이유는, 목표를 못 만들게 막으면 사용자는 하고 싶은 걸 포기하는 게 아니라 **앱을 떠납니다.** 반면 홈이 목표 8개로 가득 차면 어느 것도 눈에 들어오지 않아 전부 실패합니다. 둘 다 피하려면 **담아두는 건 자유롭게, 오늘 집중할 것만 앞에 두는** 방식이 맞습니다.

- 우선순위는 드래그로 언제든 바꿀 수 있으므로, 상위 3개를 교체하는 것이 곧 "오늘의 집중 대상 변경"입니다.
- 접힌 목표도 **기록과 알림은 정상 동작**합니다. 화면에서만 접히는 것이지 중단이 아닙니다.
- 다만 알림 상한에 걸리면 접힌 목표부터 발송이 밀립니다.
- 활성 목표가 5개를 넘으면 집사가 한 번 안내합니다. (차단 ✕, 안내 ○)

> 논의 필요: 노출 개수 3개를 고정할지, 설정에서 조절(2~5개) 가능하게 할지.

### 3.8 화면 구성 (UI/UX)

#### ① 홈 — 오늘

**카드 리스트형으로 결정** (잠정, 변경 가능). 목표별 진행률 카드를 세로로 쌓는 구조입니다. 시각이 고정되지 않는 목표(물 등)도 자연스럽게 담기고, 목표 개수가 늘어도 깨지지 않으며, Compose `LazyColumn`으로 구현이 단순합니다.

레퍼런스([ref_daily-dashboard-1.png](../reference/ref_daily-dashboard-1.png))의 타임라인형은 홈에서는 보류하되 **⑥ 하루 루틴 화면에서 살립니다.**

홈에 반드시 있어야 할 정보:

```
┌─────────────────────────────┐
│ (아바타) 집사 멘트 1줄         │
│  "3일 연속 기록하고 계십니다."   │
├─────────────────────────────┤
│  최근 2주 기록                │
│  ■ ■ □ ■ ■ ■ ■               │
│  ■ ■ ■ □ ■ ■ ▨   24/32일 기록 │
├─────────────────────────────┤
│ 📖 불변의 법칙                │
│    오늘 23쪽 중 10쪽           │
│    [■■□□□]        [ + 입력 ]  │
│    전체 142/380쪽 · D-43      │
├─────────────────────────────┤
│ 💧 물 마시기                  │
│    1,200 / 2,000ml           │
│    [+200] [+500]  🔄 자동연동  │
├─────────────────────────────┤
│ 🏃 주 3회 운동                │
│    이번 주 2/3회              │
├─────────────────────────────┤
│        ▼ 목표 2개 더보기       │
└─────────────────────────────┘
```

**기록 스트립 (상단)**

동기부여 모델의 핵심 장치입니다. 종합 달성률 퍼센트 대신 **최근 2주치 기록 그리드**를 올립니다. 퍼센트는 오늘 하루의 성적표라 못한 날엔 보기 싫어지지만, 기록 그리드는 **쌓인 것**을 보여주기 때문에 못한 날에도 앱을 열게 만듭니다.

- 한 칸 = 하루. **뭐라도 기록한 날은 칠해집니다** (완전 달성 ■ / 부분 달성 ▨ / 기록 없음 □)
- 빈 칸은 회색. 붉은색이나 ✕ 표시는 쓰지 않습니다.
- 옆에 "24/32일 기록" 같은 **꾸준함 지표**를 둡니다.
- 탭하면 전체 기록 캘린더로 이동합니다.

**카드 설계 원칙**

- 카드 하나에서 **오늘 할 몫 / 지금까지 한 양 / 전체 진척**이 모두 보여야 합니다. 상세 화면에 들어가야만 알 수 있으면 안 됩니다.
- 입력 액션은 카드 안에서 끝냅니다 (퀵 액션 버튼 또는 `+`).
- **펼쳐지는 카드는 우선순위 상위 3개까지.** 나머지는 하단 "더보기"로 접습니다 (3.7 참고).
- 달성 완료한 목표는 하단으로 내리고 축약합니다.
- 카드 탭 → 목표 상세로 이동.

#### ② 목표 상세

- 전체 진행률 (목표치 대비)
- **달력 히트맵** — 동기부여 모델의 두 번째 장치. 기록한 날의 농도를 표시합니다. 화면 상단에 크게 둡니다.
- **누적 성취 문구** — "지금까지 142쪽. 책 한 권의 37%입니다" 처럼 쌓인 양을 사람이 읽을 수 있는 말로 환산
- **페이스 그래프**: 계획선 vs 실제선 — "지금 앞서는지 뒤처지는지"를 한눈에
- 연속 기록 (streak)
- 기록 이력 리스트 (수정/삭제)
- 목표 수정 / 마감일 연장 / 보관

#### ③ 목표 생성 (스텝 위저드)

`유형 선택 → 목표치·마감일 → 측정 방식 → 알림 설정 → 현실성 검증 결과`

각 단계에서 집사가 코멘트를 달아주면 온보딩 자체가 제품 경험이 됩니다.

#### ④ 하루 루틴

3.1에서 설명한 **생활 패턴을 타임라인으로 보고 편집하는 화면**입니다. 레퍼런스 이미지의 구조를 여기에 적용합니다.

```
┌─────────────────────────────┐
│  평일  |  주말               │
├─────────────────────────────┤
│ 07:00 ⏰ 기상                │
│         │                   │
│ 08:00 🍳 아침                │
│         │                   │
│ 09:00 💼 출근 ─────┐          │
│                  │ 방해금지  │
│ 18:00            ─┘          │
│                             │
│ 19:00 🏃 운동     🔗 주3회운동 │
│ 22:00 📖 독서     🔗 불변의법칙 │
│ 23:30 🌙 취침                │
└─────────────────────────────┘
          [ + 블록 추가 ]
```

- 블록 종류: **고정 블록**(기상/식사/출퇴근/취침 — 온보딩에서 받은 값) + **사용자 블록**(자유 추가)
- 블록에 **목표를 연결**하면 그 시각이 해당 목표의 알림 시점이 됩니다. 연결 안 된 목표는 집사가 자동 배치합니다.
- 블록을 **길게 눌러 이동 / 시간 조정 / 삭제**
- 평일 / 주말 탭 분리
- 오늘 날짜일 때는 **현재 시각 인디케이터**를 표시합니다.

> 이 화면을 홈의 뷰 전환 탭으로 넣을지, 별도 탭으로 둘지는 논의가 필요합니다.
> 루틴은 매일 바뀌는 게 아니라 가끔 편집하는 설정에 가까우므로 **별도 탭 쪽**이 맞아 보입니다.

#### ⑤ 리포트

- 주간/월간 달성률
- 목표별 비교
- 요일별·시간대별 달성 패턴 ("화요일에 자주 실패합니다")
- **꾸준함 지표** — "이번 달 32일 중 24일 기록" 처럼 달성률과 별개로 참여 일수를 보여줍니다
- 집사의 주간 총평

#### ⑥ 설정

- 생활 패턴 / 하루 루틴 수정
- 집사 설정: 이미지 교체 / 이름 / 페르소나 변경
- 알림 상한 / 방해 금지 시간대
- 홈 노출 목표 개수
- Health Connect 연동 관리
- 데이터 내보내기 / 가져오기 (파일)

    name: String,                // 미입력 시 "집사"
    persona: ButlerPersona,      // HARSH / CALM / ANXIOUS
    imagePath: String?,          // 앱 내부 저장소로 복사한 파일 경로. null이면 기본 이미지
)

// 목표
Goal(
    id, title,
    type: GoalType,              // CUMULATIVE / TARGET_VALUE / RECURRING / FREQUENCY / CHECKLIST
    direction: Direction,        // UP (이상 달성) / DOWN (이하 유지)
    pacingPeriod: PacingPeriod,  // DAY / WEEK / MONTH
    unit: String,                // "쪽", "ml", "kg", "걸음", "원"
    targetValue: Double,         // DOWN이면 '상한값'
    startValue: Double,
    startDate, dueDate: LocalDate?,
    measurementCadence: Cadence?, // 도달형 전용: DAILY / WEEKLY / EVENT
    trackingMode: TrackingMode,  // MANUAL / AUTO
    healthDataType: HealthDataType?,
    priority: Int,
    restDays: Set<DayOfWeek>,
    status: GoalStatus,          // ACTIVE / COMPLETED / ARCHIVED
)

// 체크리스트형 목표의 항목
ChecklistItem(id, goalId, title, order: Int, completedAt: Instant?, dueDate: LocalDate?)

// 하루 루틴 블록
RoutineBlock(
    id, title,
    startTime, endTime: LocalTime,
    dayType: DayType,            // WEEKDAY / WEEKEND
    kind: BlockKind,             // FIXED(기상·식사·취침 등) / USER
    linkedGoalId: String?,       // 연결된 목표. 있으면 이 시각에 알림 발송
    iconKey: String?,
)

// 일자별 기록 요약 — 홈 기록 스트립 / 히트맵용 (파생 캐시)
DailyRecord(date, goalId, achievedAmount: Double, quota: Double, state: RecordState)
// RecordState: FULL(달성) / PARTIAL(부분 기록) / NONE(기록 없음)

// 주기별 할당량 (주기 전환 시 재계산)
// DOWN 목표에서는 quota가 '예산 상한'으로 해석됨
PeriodQuota(goalId, periodStart: LocalDate, quota: Double, carriedOver: Double)

// 진행 기록
ProgressEntry(
    id, goalId,
    recordedAt: Instant,
    amount: Double,
    source: EntrySource,         // MANUAL / HEALTH_CONNECT / NOTIFICATION_ACTION
)

// 알림 스케줄
NotificationSchedule(goalId, scheduledAt, category, status)

## 5. 기술 스택 고려사항

**서버 없이 로컬 온리로 결정.** 모든 데이터는 기기 안에만 저장하고 네트워크 통신을 하지 않습니다. 계정·로그인·동기화가 전부 빠지므로 구현 범위가 크게 줄고, 건강 데이터를 다루는 앱에서 개인정보 처리 부담도 사라집니다.

대신 **기기 변경·앱 재설치 시 데이터가 전부 날아가는 문제**가 생깁니다. 이건 백업 기능으로 막습니다.

- 설정에서 전체 데이터를 **JSON(+이미지) 파일로 내보내기 / 가져오기**
- 저장 위치는 SAF(`ACTION_CREATE_DOCUMENT`)로 사용자가 직접 지정 — 저장소 권한 불필요
- Android `allowBackup` / Auto Backup 활성화도 함께 검토

현재 프로젝트는 Kotlin + Jetpack Compose + Material3 구성입니다. 추가로 필요한 것들:

| 영역 | 후보 | 메모 |
| --- | --- | --- |
| 로컬 DB | Room | 유일한 저장소. 네트워크 계층 없음 |
| 설정 저장 | DataStore | UserProfile, Butler, 앱 설정 |
| DI | Hilt | 모듈 규모 고려 시 도입 권장 |
| 백그라운드 | WorkManager | 자정 재계산, 헬스 동기화 |
| 알림 스케줄 | AlarmManager (`setExactAndAllowWhileIdle`) | 정시성이 중요하므로 WorkManager만으로는 부족 |
| 헬스 연동 | Health Connect Client | `POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM` 권한 함께 처리 |
| 이미지 선택 | Activity Result `PickVisualMedia` | Photo Picker, 저장소 권한 불필요 |
| 이미지 로딩 | Coil | 집사 아바타 표시 및 캐싱 |
| 차트 | Vico 또는 Compose Canvas 직접 구현 | 페이스 그래프용 |

**선제적으로 확인해야 할 리스크**

- 제조사별 배터리 최적화(삼성, 샤오미 등)로 알림이 지연·누락되는 문제 → 배터리 최적화 예외 요청 플로우 필요
- Android 13+ 알림 권한 런타임 요청
- Android 14+ `SCHEDULE_EXACT_ALARM` 정책 제한
- 로컬 온리이므로 **DB 마이그레이션 실수 = 사용자 데이터 영구 손실**. Room 스키마 변경 시 마이그레이션 테스트 필수

### 6.5 시즌 1 (v1.0) 확정 범위

킥오프 자료가 **"시즌 1은 아래 세 가지에 집중"** 이라고 명시했습니다. 이 셋만 합니다.

**① 목표 만들기**

- [ ] 독서 · 공부 · 운동 등 **수량형 목표**의 목표량과 기간 입력
- [ ] 목표 유형은 **누적형 하나**, 방향 `UP`, 주기 `DAY` 고정
- [ ] 중도에 목표 수정 가능 (목표량 · 마감일 변경)
- [ ] 목표 생성 시 비현실적 할당량 경고 (단순 버전)

> 스키마에는 `direction` / `pacingPeriod` / `type`을 **처음부터 넣어둡니다.**
> 시즌 2~3에서 유형이 늘어날 때 컬럼을 추가하면 마이그레이션이 번거롭고, 로컬 전용이라 실수 비용이 큽니다.

**② 오늘 화면**

- [ ] 오늘 할 분량을 집사가 계산해 표시
- [ ] 목표 카드 리스트 (오늘 할 몫 / 한 양 / 전체 진척 / D-day)
- [ ] 홈 노출 상위 3개 + 더보기 접기
- [ ] **기록 스트립** (최근 2주, 부분 달성도 칠함)

**③ 기록하기**

- [ ] 한 만큼 수동 입력
- [ ] 남은 날 기준 **자동 재계산**
- [ ] 기록 수정 · 삭제
- [ ] 목표 상세: 진행률 + **달력 히트맵** + 기록 이력

**시즌 1에서 뺀 것** — 알림, 집사 말투·외형, 하루 루틴, 헬스 연동, 도달형·반복형·빈도형·체크리스트형 목표, 감량 건강 가드레일, 리포트, 백업

> 건강 가드레일을 뺀 이유는 **시즌 1에 체중·BMI 목표 자체가 없기 때문**입니다.
> 도달형 목표를 넣는 시즌에 가드레일도 반드시 같이 들어가야 합니다. 순서가 바뀌면 안 됩니다.

### 6.6 시즌 2 이후 배치안

시즌 1 이후 순서는 함께 결정하기로 했으므로 **제안**입니다.

| 시즌 | 넣을 것 |
| --- | --- |
| **시즌 2** — 프로젝트와 설정 | 집사 말투 3종 · 외형 업로드 · 이름 / 로컬 알림 + 마감 임박 알림 / 반복형 · 빈도형 목표 / `DOWN` 방향 목표 / 알림 액션 기록 |
| **시즌 3** — 시간표형 집사 | 하루 루틴 타임라인 + 블록 ↔ 목표 연결 / 생활 패턴 기반 알림 자동 배치 / 하루 달성률 |
| **시즌 4** — 생활 관찰 | 주간·월간 리포트 + 꾸준함 지표 / 요일·시간대 패턴 분석 / 목표 난이도 조정 제안 / 실행 패턴 학습 |
| 시즌 미정 | 도달형(체중·BMI) + **건강 가드레일** / Health Connect 연동 / 체크리스트형 / 데이터 내보내기 / 위젯 |

### 6.7 서버가 생긴다면 (장기 아이디어)

현재는 **로컬 전용으로 결정**했고, 앱 내 커뮤니티·그룹 기능도 킥오프에서 보류로 정리됐습니다. 서버를 붙이는 선택을 하게 되면 열리는 방향만 적어둡니다.

- 카테고리별 리더보드 — 독서·운동·절제 등 카테고리별 달성률 랭킹
- 계정 / 기기 간 동기화
- 친구 추가, 같은 목표 함께하기

**리더보드를 넣을 때 미리 생각해둘 것**

| 쟁점 | 메모 |
| --- | --- |
| 비교가 동기를 꺾을 수 있음 | "미완료는 실패가 아니다"라는 이 앱의 기준선과 정면으로 부딪힙니다. 1등 랭킹보다 **비슷한 페이스의 사람들과 묶는 방식**이 맞을 수 있습니다 |
| 수치 조작 | 수동 입력 기반이라 자기신고 수치를 그대로 랭킹에 쓰면 의미가 없습니다. 자동 연동 목표만 집계하거나 순위 대신 참여 지표를 쓰는 안 |
| 개인정보 | 체중·BMI 같은 민감 정보는 랭킹 대상에서 제외해야 합니다. 킥오프 기본 규칙에도 개인정보 보호 조항이 있습니다 |
| 서버 비용·운영 | 프로젝트 범위를 넘어설 수 있습니다 |

## 7. 결정된 사항 (2026-10-18)

| 항목 | 결정 |
| --- | --- |
| 홈 화면 형태 | **카드 리스트형** — 잠정 결정이며 추후 변경 가능 |
| 집사 캐릭터 | **사용자가 직접 이미지 업로드**. 기본 이미지도 함께 제공, 말투는 페르소나 선택 |

| **동기부여 방식** | **기록 트래커가 1차 동력.** 부분 달성도 기록으로 칠하고, 빈 칸을 벌하지 않음. "느려도 꾸준히" 톤 (1장 참고) |

| **목표 개수 제한** | 생성은 무제한, **홈에 펼치는 것만 상위 3개 + 더보기**로 접기 (3.7 참고) |
| **하루 루틴 화면** | **추가.** 생활 패턴을 타임라인으로 보고 편집, 블록에 목표 연결. 레퍼런스의 타임라인 UI를 여기에 적용 (3.8 ④ 참고) |

## 8. 아직 논의가 필요한 항목

### 8.1 목표 실패 처리 (회의 안건)

마감일이 지났는데 목표를 못 채운 경우를 어떻게 다룰지. UX의 성격을 결정하는 문제라 따로 논의가 필요합니다.

**핵심 쟁점**: 이 앱이 *실패를 기록하는 앱*인지, *실패를 없애주는 앱*인지.

> 킥오프 자료의 **"미완료는 실패가 아니다"** 가 사실상 방향을 정해줍니다. A안(실패 확정)은 이 문장과 충돌하므로 탈락입니다.
> 남은 선택지는 B·C·D이며, 그중 D가 이 문장에 가장 가깝습니다.

| 안 | 동작 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 실패 확정 | "미달성"으로 종료, 기록에 남김 | 목표의 무게가 생김, 기록의 정직성 | 이탈 위험. 실패 경험은 앱을 지우게 만듦 |
| B. 자동 연장 | 남은 양 기준으로 마감일 자동 연장 | 좌절감 없음, 계속 쓰게 됨 | 마감일이 무의미해져 목표가 느슨해짐 |
| C. 사용자 선택 | 마감일에 "연장 / 목표 조정 / 종료" 중 선택 | 통제권이 사용자에게 | 선택 피로, 모달 귀찮음 |
| D. 자동 마감 + 부분 달성 표기 | 종료하되 "380쪽 중 310쪽 — 82% 달성"으로 표현 | 실패가 아닌 성취로 프레이밍 | 애매한 종료감 |

> 개인 의견: **D를 기본으로 하고 직후에 "이어서 할까요?" 재시작을 제안**하는 방식이 좋아 보입니다.
> 실패 낙인을 피하면서 마감일의 의미도 지킬 수 있습니다. 다만 회의에서 정합시다.

**같이 정해야 할 것들**

- 종료된 목표를 리포트 통계에 포함할지
- 중도 포기(사용자가 직접 삭제)와 마감 미달성을 구분할지
- 마감 미달성으로 끝난 목표도 **기록 스트립에는 그대로 남깁니다.** 동기부여 모델상 쌓인 기록을 지우면 안 됩니다

> 마감일 당일/직전 경고는 **보내는 것으로 확정**했습니다. (3.5 참고)
> 다만 알림 기능 자체가 시즌 2이므로, **시즌 1에서는 화면 안의 D-day 표기**로만 처리합니다.

### 8.2 기타 미결 항목

1. **알림 공격성의 수위** — "표독 집사"가 어디까지 세게 말해도 되는지 기준선. 재미와 불쾌감의 경계. (단, 건강 경고는 페르소나를 타지 않기로 확정)
2. **집사 이미지 장수** — 1장만 받을지, 상황별(평시/칭찬/독촉) 여러 장을 받을지.
3. **`DOWN` 목표의 미기록 처리** — 기록이 없는 날을 "지킨 날"로 볼지, "모름"으로 둘지. (3.2 제안은 "지킨 날")
4. **`DOWN` 목표의 초과분 이월** — 어제 초과한 양을 오늘 예산에서 깎을지, 주기마다 리셋할지. (3.3 제안은 "리셋")
5. **체크리스트형을 넣을 것인가** — 정량 목표 앱의 정체성에서 벗어난다는 반론이 가능합니다. 제외하고 누적형으로 대체해도 되는지.
6. **건강 가드레일의 차단 기준** — BMI 18.5로 둘지 더 보수적으로 갈지. "차단"이 생성 불가인지 강한 경고 후 진행 가능인지.
7. **홈 노출 개수** — 3개 고정인지, 설정에서 2~5개 조절 가능하게 할지.
8. **하루 루틴의 위치** — 홈의 뷰 전환 탭인지 별도 탭인지. (초안 제안은 별도 탭)
9. **기록 스트립의 "부분 달성" 기준** — 1쪽만 읽어도 칠할지, 할당량의 일정 비율 이상일 때만 칠할지.
